# 《山海来信》设计文档 v0.2

> 一款以《山海经》神兽为主角，融合放置旅行、随机叙事、书信互动与轻收集的国风纯静态网页游戏。
> 定位：**B 随机叙事为主轴，A 治愈放置为节奏，C 探索收集为长期目标**。

---

## 一、核心循环

```
准备行囊 → 选择倾向 → 神兽出发（真实时间流逝）
    ↓                                    ↑
家园/图鉴 ← 收取纪念品 ← 读信 → 回信（影响记忆）
```

与《旅行青蛙》的关键差异：**玩家不是只能等，而是「影响倾向但不确定结果」，
且归来后能看到「因为什么所以发生了什么」的归因回显。**

---

## 二、对 GPT 方案的取舍与增量

GPT 给的七个系统方向整体成立，但直接全做会撑爆首版。我的判断如下。

### 2.1 采纳（首版就做）

| 系统 | 理由 |
|---|---|
| ① 神兽性格养成（标签化） | 成本极低，收益最高。性格 = 一组 tag，直接进事件权重公式 |
| ② 随机旅行奇遇 | 主玩法，必须做 |
| ③ 山海图鉴 | 长期目标载体 |
| ④ 书信互动（回信三选一） | 本作最差异化的点，且对静态网页极友好（纯条件分支） |
| 连续事件链（记忆） | 让叙事有连续性，是「第二次旅行不像第一次」的唯一实现方式 |

### 2.2 降级（首版只埋数据，不开系统）

| 系统 | 处理 |
|---|---|
| ⑥ 神兽之间结伴旅行 | 首版只做「同行信物」：某神兽带回的物品，会以小概率出现在另一只的信里。系统层留 `bond` 字段，不开放玩法 |
| ⑦ 季节/节日事件 | 首版按**城市天气**做随机覆盖层（雨/雪/晴/夜），不接真实节日日历，避免「错过就没有」的焦虑 |

### 2.3 我的三条增量（GPT 没提，但我认为是关键）

**① 主进度条应该是「认知弧线」，不是收集率。**
收集率会驱动玩家刷，与"松弛感"冲突。真正值得做主线的，是 GPT 第十节那条
「从把现代文明当神迹，到理解人间自有其法」。把它做成显式四阶段：

| 阶段 | 名称 | 神兽眼中的人间 |
|---|---|---|
| 0 | 初见 | 处处是神迹（高铁 = 铁甲异兽） |
| 1 | 好奇 | 开始追问"为什么"（研究铁路图） |
| 2 | 领会 | 承认人类不用法术也做到了 |
| 3 | 回信 | 想给人间写点什么（终章信件） |

每只神兽独立推进，终章是**玩家专属结局**，而不是图鉴 100%。

**② 归来必须有「归因回显」。**
玩家做了选择就要看到因果，否则三选一就等于假选择。归来界面明确显示：

> 带上了「油纸伞」→ 它拐进了雨里的巷子
> 你上回说「听听她的故事」→ 它记住了，这次主动坐下来听人讲话

这条比多写 20 个事件更能提升"我的选择有意义"的感受。

**③ 世界状态随收集而变化（最省的涌现感）。**
某只神兽带回《铁路研究手稿》后，**所有**神兽去**任何**城市都有小概率触发
"翻出白泽的手稿查地图"的插曲。不需要新美术、不需要新系统，只需要事件库里加
一句 `requires: {souvenir:'rail-notes'}`，就能让玩家感到"世界被我改变了"。

### 2.4 两个必须正视的现实约束

**真实等待时长。** 旅行青蛙是 2–6 小时，但网页首版若照搬，你和试玩者当天体验不到
第二个循环。方案：**双时钟** —— 默认真实时长（短途 20 分钟 / 长途 1 小时），
另给一个「静心沙漏」按钮（消耗一次，立刻结算），首日不限次。

**内容生产成本才是最大风险，不是代码。**
事件必须做成数据驱动模板，且支持 `chain`（事件链）与 `requires`（条件）字段。
公式：

```
候选事件 = 城市标签 × 神兽性格tag × 携带道具 × 已有记忆(memory) × 世界解锁(worldFlags)
→ 加权随机 → 产出 来信 + 纪念品 + memory 写入
```

## 三、首版（v0.1）范围

| 项 | 规模 |
|---|---|
| 神兽 | 3（白泽 / 九尾狐 / 青鸟），精卫作为 v0.2 解锁 |
| 城市 | 6（西安 / 成都 / 苏州 / 杭州 / 敦煌 / 哈尔滨） |
| 事件 | 24 条 + 3 条事件链（每链 3 段） |
| 来信 | 事件链信件 + 随机信件，合计 ~45 封 |
| 纪念品 | 30 件（含 6 件稀有 / 3 件传说） |
| 家园 | 山海驿站 1 座，12 个摆放槽位 |
| 回信 | 每封关键信 3 个选项，写入 memory |
| 图鉴 | 分四类，合成《新山海经》进度 |
| 存档 | localStorage + 导出/导入 |

## 四、推进路线（建议分四步，每步可独立验收）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **S1 骨架** | 目录 + 引擎（rng/存档/状态）+ 一次完整旅行闭环（出发→等待→归来→收信→收纪念品） | 能用 3 只神兽跑通 10 次旅行不报错 |
| **S2 内容** | 24 事件 + 30 纪念品 + 6 城市数据 + 事件链 | 同一神兽连去 3 次西安，信件不重样且能连成故事 |
| **S3 差异系统** | 回信三选一 + 认知弧线四阶段 + 归因回显 + 家园摆放 | 不同回信能让后续信件走向不同分支 |
| **S4 美术与打磨** | 替换为 AI 生成素材（见 ART-LIST.md）+ 动效/音效 + 导出导入 + 移动端适配 | 手机竖屏能玩，首屏 3 秒内有反馈 |

**顺序不能颠倒**：先 S1 跑通闭环，再灌内容。否则内容写完发现引擎改不动。

## 五、技术约束（纯静态）

- 无构建、无框架、无 CDN，普通 `<script>` 顺序加载，`window.SH` 全局命名空间
- 数据为 JS 常量（`file://` 下 `fetch()` 会被拦截）
- 旅行结算**不依赖后台常驻**：出发时写入 `departAt / returnAt / seed / 选择`，
  重开页面时按时间差结算，用种子随机保证结果确定
- 已知边界：清缓存会丢档（已提供导出导入）；改系统时间可作弊（单机游戏，可接受）

---

## 六、长期主题

上古的山海图已久未更新，神兽们渐渐不了解如今的人间。
玩家经营一座山海驿站，送它们走进现代城市，收集关于新世界的见闻。
每次旅行带回一页游记、一幅图画、一件纪念品或一段新的理解，
最终汇成一本只属于你的《新山海经》。

## 七、界面与交互规范（v0.2）

> v0.2 的目标：守住「绘本小屋」气质，同时让长页面可读、手机可点、
> 素材缺失时有稳定兜底，并且不再出现图片盖住按钮这类硬伤。

### 7.1 视觉层级（从后到前）

1. **场景横幅**：`home-hall` 只铺顶部 `clamp(220px, 42vh, 380px)`，底部渐隐到纸色；
   不再把 16:9 图拉成几屏高，长页面（图鉴 / 驿站）不会出现巨型放大背景。
2. **纸面内容**：行囊 / 图鉴 / 驿站铺一张高不透明暖纸（约 95%），带柔和大投影；
   正文与场景图在视觉上分层，避免“字压在画上”。
3. **匾额**：全站唯一 H1，副标题与三个指标（新山海经 / 纪念品 / 待回信）。
4. **底部木牌导航**：固定 + 顶部圆角 + 安全区；当前页用深木色底和 `aria-current`。
5. **Toast**：独立图层，位于导航之上；只更新自身，不重绘页面、不抢键盘焦点。

### 7.2 设计令牌

| 类别 | 令牌 |
|---|---|
| 纸色 | `--paper #f6ecdb` / `--paper-2 #efe2cb` / `--cream #fdf7ea` |
| 墨色 | `--ink #453729` / `--ink-2 #7a6552` / `--muted #77624f` |
| 强调 | `--cinnabar #c0563f`（色块） / `--cinnabar-ink #a8442f`（文字） / `--gold #d4a24e` |
| 辅助 | `--sage #7d9b7e` / `--sage-ink #4f7050` / `--wood-deep #6b4a2b` |
| 焦点 | `--focus #9c3f2c`，3px 实线 + 3px 偏移，仅 `:focus-visible` |
| 字号 | 10.5 / 11.5 / 12.5 / 14 / 16 / 21 / 25px；正文行高 1.75，信纸 2.05 |
| 间距 | 4 / 6 / 8 / 10 / 12 / 16 / 20 / 24（8 的倍数为主） |
| 圆角 | 10（藏品）/ 14（按钮）/ 18–22（纸面）/ 26（场景）/ 999（胶囊） |
| 阴影 | `--shadow-soft` / `--shadow-lift` / `--shadow-sheet`，不用 1px 灰边框 |

规则：**朱砂色只做色块**，小字一律用 `--cinnabar-ink`；次要文字用 `--muted`（纸面上 ≥4.5:1）。
透明底素材用 `object-fit: contain`，场景/城市照片用 `cover`；图片本身 `pointer-events: none`。

### 7.3 响应式

- 内容最大宽度 660px；断点 560px。已验证 1280 / 390 / 320 无横向溢出。
- 庭院三张神兽卡：`flex` + `172–216px`，桌面三列，390px 两列 + 第三张居中，320px 单列。
- 行囊道具：桌面 4 列，手机 2 列；图鉴木架手机 4 列；驿站格位手机 4 列。
- 固定导航高度 `--dock-h`（72 / 68），`.room` 底部预留 `dock + 30px + safe-area`，
  任何内容（包括「送它出发」和底部设置）都能滚到导航之上。
- 点击目标：小按钮 ≥34px，底栏瓦片 ≥54×52；`env(safe-area-inset-bottom)` 适配全面屏。

### 7.4 状态与兜底

| 状态 | 处理 |
|---|---|
| 空信箱 | 信封面 + 一句引导 + 「去准备行囊」按钮 |
| 神兽不在 | 神兽卡置灰标「在路上」，选它给出提示；出发按钮旁说明原因 |
| 无可摆纪念品 | 选择器显示「先送神兽出门吧」；取走按钮在空位时禁用 |
| 图片缺失 | 神兽 → 内联 SVG；纪念品 → Emoji；城市 → 名字渐变；道具 → Emoji；底栏 → SVG |
| 可选素材 | 在 `assets/images/art-manifest.js` 登记后才请求，避免反复 404 |
| 导入失败 | 明确提示「不是有效 JSON / 缺少神兽数据」，不会留下半损坏存档 |
| 动效敏感 | `prefers-reduced-motion: reduce` 时关闭浮动、闪光、转场 |

### 7.5 交互约定

- 切换底部页签：清空“展开的信 / 打开的选件器”，回到页首；行囊里的选择保留。
- 旅行归来：**只有玩家正在庭院时**才自动翻到信箱；在看书 / 摆件时只弹提示，不打断。
  自动打开优先选「可回信」的那封，阶段信留在列表顶部。
- 信件：信封头是按钮，`aria-expanded` 标记展开；支持 Esc 收起并回到该信封。
- 回信：访客来信代表“驿站”，回信记忆写入全部神兽；神兽来信只写入本人。
- 驿站摆件：同一件纪念品再放到别处 = **移动**，不报错；「挪过来」标签提示来源。
- 设置：导出 / 导入 / 重置收进「设置与存档」，避免主界面误触重置。
- Toast：`aria-live="polite"`，3.2s 自动消失；错误类用暖褐色 `toast-warn` 区分。

### 7.6 验收清单

- [ ] 1280 / 390 / 320 三种宽度无横向滚动条，底栏不遮主按钮
- [ ] 点击任意神兽卡不被其他图片拦截；行囊可选中 3 件、第 4 件给提示
- [ ] 一次完整闭环：出发 → 静心沙漏 → 归来 → 读信 → 回信 → 图鉴 +1
- [ ] 双站旅行：出行只 +1，两封信的「因为」各自独立，阶段信排在最前
- [ ] 同一记忆被重复选择后，回声事件仍能触发（记忆条件为“至少 N 次”）
- [ ] 图鉴「古今遗珍」在看完 8 条相关事件后达到 100%
- [ ] 键盘：Tab 有 3px 焦点环，Esc 关选件器 / 信，回信后焦点回到信封头
- [ ] 控制台 0 报错；未登记的可选素材不发请求

## 八、v0.2 修复记录

| 问题 | 根因 | 修复 |
|---|---|---|
| 神兽大图盖住相邻卡片、按钮点不到 | 缺少 `.art / .art-img` 尺寸约束，640px 原图直接参与布局 | 容器定尺寸 + 图片绝对定位 + `contain`/`cover` + `pointer-events:none` |
| 场景图在长页面被拉成几屏高 | 背景图 `inset:0` 跟随内容高度 | 改为顶部横幅 + 渐隐纸色 |
| 行囊主按钮被底部导航压住 | 固定导航覆盖内容，缺少等效底部留白 | `--dock-h` + safe-area 预留，三档宽度实测可滚到按钮上方 |
| 天气图标掉进信件正文 | `.sheet > *` 的 `position:relative` 特异性高于 `.sheet-weather` | 排除天气节点，恢复绝对定位并加圆形纸底 |
| 两站旅行被记成两次出行 | `travels` 在每站循环内自增 | 每次旅行只 +1 |
| 第二封信继承了第一站的「因为」 | 归因数组在循环外共享 | 每站独立归因，最多 5 条 |
| 阶段信显示在旧信之后 | 阶段信直接 push 到旅行信末尾 | 阶段信 `unshift`，最新阶段在最上 |
| 回声事件在重复选择后失效 | 记忆条件用严格相等，累计值变成 2 就匹配不上 | 改为“至少 N 次”（`>=`） |
| 图鉴「古今遗珍」永远到不了 100% | 目标 10 条，事件库只有 8 条 | 目标调整为 8；扩充事件后再同步上调 |
| 相同城市一趟去两次 | 固定城市事件未检查已访问城市 | 固定城市也加入排除 |
| 访客回信只记到白泽身上 | 访客信硬编码 `beastId: 'baize'` | 访客信记忆写入全部神兽，且不再提升单个神兽见闻 |
| 摆件重复放置报错 | 校验到重复直接返回失败 | 自动从旧格位移动，并提示「挪到新位置了」 |
| 导入旧/坏存档后界面崩溃 | 直接替换 `SH.state`，缺 `settings` 等字段 | 导入前统一归一化并给出明确错误 |
| 设置/存档/重置按钮过于显眼 | 全部平铺在页脚 | 收进可展开的「设置与存档」 |
| 每次 Toast 都整页重绘、丢焦点 | `ui.toast` 调 `ui.render` | Toast 独立图层；渲染时保存/恢复焦点与滚动位置 |
| 图鉴/驿站访客条件显示英文 tag | 直接 `join('/')` | 统一中文标签映射 `SH.sys.tagName` |
| 可选素材每次渲染都 404 | 先请求图片再回退 SVG | `art-manifest.js` 登记 + 会话内缺失缓存 |
